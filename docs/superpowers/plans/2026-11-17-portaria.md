# Sistema de Portaria Sacchelli — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sistema web de portaria (Vercel + Supabase) com agente local que integra equipamento Intelbras Bio-T (face e digital) via Modo Online e CGI.

**Architecture:** Monorepo npm workspaces: `packages/core` (regras puras), `apps/web` (Next.js 14 App Router), `agent` (Node 20). Banco = migrations SQL do Supabase. Agente ↔ nuvem por HTTPS com token; agente ↔ aparelho por HTTP na LAN.

**Tech Stack:** TypeScript 5, Next.js 14, Tailwind 3, @supabase/supabase-js 2 + @supabase/ssr, Recharts, Vitest, Node 20 (`node:http`, `fetch`).

**Spec:** `docs/design.md`

## Global Constraints
- Idioma da UI: pt-BR. Fuso: `America/Sao_Paulo` em toda data exibida e em "fim do dia".
- Nomes de tabelas = DER do PDF em snake_case minúsculo (`pessoa`, `visitante`, `funcionario`, `setor`, `motivo_visita`, `visita`, `autorizacao_acesso`, `identificacao_biometrica`, `dispositivo`, `registro_acesso`, `evento_dispositivo`, `usuario`, `perfil`, `permissao`, `perfil_permissao`, `log_auditoria`, `comando_dispositivo`).
- Perfis: `PORTEIRO`, `GESTOR`, `ADMIN`.
- Motivos de negativa (enum do PDF): `NAO_RECONHECIDO, PESSOA_NAO_CADASTRADA, SEM_AUTORIZACAO, AUTORIZACAO_EXPIRADA, AUTORIZACAO_REVOGADA, PESSOA_BLOQUEADA, FALHA_RECONHECIMENTO, FALHA_COMUNICACAO, DISPOSITIVO_INDISPONIVEL`.
- Cores: navy `#0B2A5B`, azul `#1F4E99`, amarelo `#F2C200`, verde `#1F9D55`.
- Nada é criado em Vercel/Supabase: só arquivos + `docs/DEPLOY.md`.
- Foto facial nunca persiste fora de `comando_dispositivo.payload`, que é limpo após execução.
- Agente nunca recebe a service role key; usa `AGENTE_TOKEN`.

## Review Focus
- CPF digitado com/sem máscara deve achar a mesma pessoa (normalizar para 11 dígitos) — teste em Task 1.
- "Até 23:59 do dia" no fuso de São Paulo, não UTC (servidor Vercel roda em UTC) — teste em Task 1.
- Nuvem lenta: agente responde ao aparelho antes do timeout com negação `FALHA_COMUNICACAO` — teste em Task 8.
- Evento do aparelho com UserID desconhecido ou payload em formato inesperado → negar e registrar payload bruto, nunca derrubar o agente — teste em Task 8.
- Comando que falha no aparelho fica `ERRO` com mensagem e tentativas, sem loop infinito (máx. 3) — teste em Task 8.

### Task 1: Monorepo + regras de negócio (`packages/core`)
**Files:** `package.json`, `tsconfig.base.json`, `packages/core/src/{cpf,placa,tempo,acesso,index}.ts`, `packages/core/test/*.test.ts`
**Interfaces (Produces):**
- `normalizarCpf(v: string): string`, `cpfValido(v: string): boolean`, `formatarCpf(v: string): string`
- `placaValida(v: string): boolean` (Mercosul `ABC1D23` e antiga `ABC1234`, com/sem hífen)
- `fimDoDiaSP(ref: Date): Date` (23:59:59.999 em America/Sao_Paulo)
- `avaliarAcesso(input: { pessoa: { situacao: 'ATIVA'|'INATIVA'|'BLOQUEADA' } | null; autorizacoes: { id: string; situacao: 'ATIVA'|'REVOGADA'|'ENCERRADA'; validoDe: Date; validoAte: Date | null }[]; agora: Date; sentido: 'ENTRADA'|'SAIDA' }): { permitido: boolean; motivo: MotivoNegativa | null; autorizacaoId: string | null }`
  - Ordem (fig. 10 do PDF): pessoa nula → PESSOA_NAO_CADASTRADA; não ATIVA → PESSOA_BLOQUEADA; sem autorizações → SEM_AUTORIZACAO; existe ATIVA vigente → permitido; só revogadas/encerradas → AUTORIZACAO_REVOGADA; ATIVA fora da janela → AUTORIZACAO_EXPIRADA. SAIDA sempre permitida (registra, não bloqueia).
- [ ] Testes: `cpfValido('529.982.247-25')===true`, `cpfValido('111.111.111-11')===false`, `normalizarCpf('529.982.247-25')==='52998224725'`; `placaValida('ABC-1234')`, `placaValida('BRA2E19')`, `!placaValida('AB123')`; `fimDoDiaSP(new Date('2026-11-17T02:30:00Z'))` → `2026-11-17T02:59:59.999Z` (ainda dia 16 em SP); cada ramo de `avaliarAcesso`.
- [ ] Rodar `npm test -w packages/core` → FAIL; implementar; → PASS; `git init` + commit.

- `0003`: `fn_perfil_atual()` (security definer), view `vw_presentes` (último movimento LIBERADO = ENTRADA), view `vw_eventos_hora` (contagem por hora SP e resultado, últimas 24h), trigger de auditoria em `pessoa, visita, autorizacao_acesso, usuario, dispositivo`.

- Seed: setores, motivos ("Reunião", "Entrega", "Manutenção", "Entrevista", "Visita técnica", "Outros"), 1 dispositivo "Portaria — Entrada" e 1 "Equipamento virtual" (modo SIMULADOR), funcionários de exemplo.
